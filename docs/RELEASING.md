# Выпуск CursorMotion

1. Синхронизировать версии `src/CursorMotion.csproj`, bootstrap-проекта и
   `desktop/package.json`; обновить оба README и описание выпуска.
2. Собрать EXE через `build-single-file.ps1`, проверить `tools/verify-package.ps1`.
   Верификация должна относиться к окончательным байтам EXE.
3. Проверить `git diff --cached`: никаких профилей, логов, приватных наблюдений,
   кэша, runtime-архивов или токенов. Исходники зависимостей/лицензии сохраняются.
4. Закоммитить, отправить main и дождаться CI. Создать тег `v<версия>` на точном
   проверенном commit. Workflow Release Windows независимо проверяет сборку и
   создаёт Actions artifact; сам GitHub Release не публикует.
5. Создать один черновик GitHub Release на этом теге. Прикрепить принятые EXE,
   `SHA256SUMS.txt` и `package-verification.json`. Не заменять их байтами другой
   сборки и не перезаписывать выпущенную версию.
6. Сверить tag/commit, размеры, хеши, ссылки и описание; опубликовать выпуск как
   latest. Проверить публичное скачивание и контрольную сумму.

Оформление: **CursorMotion <версия> — тема выпуска**. В начале — раскрываемый
полный English release notes; основной русский текст виден под ним. Порядок:
результат выпуска, скачивание одного EXE, изменения, нужные ограничения,
раскрываемые проверки/совместимость, автор/Telegram/лицензии.

В README и релизах указывать реальные проверки. Автотесты скрытого окна не
выдавать за живую проверку записи или поведения поверх уведомлений. Для текущей
ветки 3.10 пользователь принял моушн и края на 2K/4K, а запись NVIDIA проверил
на размере 4.5×. Этот размер — жёсткий максимум. Проверка относится к его
конфигурации; нельзя обещать совместимость со всеми драйверами.

Portable обновляется вручную после полного выхода через трей. Автообновлятора,
`latest.yml` и `.blockmap` у CursorMotion нет. Настройки остаются в AppData.
Перемещение/переименование EXE требует повторного включения автозапуска.
